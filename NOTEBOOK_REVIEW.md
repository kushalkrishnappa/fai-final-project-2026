$ ~/.pyenv/versions/pytorch/bin/python -m pip install --dry-run tensorflow
ERROR: Could not find a version that satisfies the requirement tensorflow (from versions: none)
ERROR: No matching distribution found for tensorflow
```

**Why, in plain English.** Your `pytorch` kernel runs **Python 3.14**. TensorFlow does not
publish wheels for Python 3.14 — the newest interpreter it supports is well behind that. So pip
looks for a `cp314` wheel, finds *nothing at all* (`from versions: none`, i.e. not "wrong
version" but "no versions exist for this Python"), and the import fails. This is not a bug in
your code; it is a hard platform incompatibility. Re-running `!pip install tensorflow` will
never fix it.

Replace cells 160 + 161 with:

```python
import torch
import torch.nn as nn

torch.manual_seed(42)
device = torch.device("cpu")          # or "mps" on Apple silicon


def _t(a):
    return torch.tensor(np.asarray(a, dtype=np.float32), device=device)


Xtr, ytr = _t(X_train_scaled), _t(y_train_scaled)
Xva, yva = _t(X_val_scaled),   _t(y_val_scaled)
Xte      = _t(X_test_scaled)

# Same architecture as the Keras model: 64 -> 128 -> drop -> 64 -> BN -> 64 -> 32 -> BN -> 32 -> 16 -> 1
model_scaled = nn.Sequential(
    nn.Linear(Xtr.shape[1], 64), nn.ReLU(),
    nn.Linear(64, 128), nn.ReLU(),        # L2(0.3), applied in the loss below
    nn.Dropout(0.3),
    nn.Linear(128, 64), nn.ReLU(),
    nn.BatchNorm1d(64),
    nn.Linear(64, 64), nn.ReLU(),         # L2(0.1)
    nn.Linear(64, 32), nn.ReLU(),
    nn.BatchNorm1d(32),
    nn.Linear(32, 32), nn.ReLU(),         # L2(0.5)
    nn.Linear(32, 16), nn.ReLU(),
    nn.Linear(16, 1),
).to(device)

# Keras `kernel_regularizer=l2(w)` has no direct optimizer equivalent (weight_decay would hit
# every layer), so add the penalty for exactly the three regularised layers by hand.
l2_layers = {2: 0.3, 8: 0.1, 13: 0.5}     # Sequential index of the Linear -> lambda
optimizer = torch.optim.Adam(model_scaled.parameters(), lr=1e-3)
criterion = nn.MSELoss()
loader = torch.utils.data.DataLoader(
    torch.utils.data.TensorDataset(Xtr, ytr), batch_size=16, shuffle=True)


class History:            # keeps the downstream `history.history` cell working unchanged
    def __init__(self):
        self.history = {"loss": [], "val_loss": [],
                        "mean_absolute_error": [], "val_mean_absolute_error": []}


history = History()
EPOCHS = 50
for epoch in range(EPOCHS):
    model_scaled.train()
    running = running_mae = 0.0
    for xb, yb in loader:
        optimizer.zero_grad()
        out = model_scaled(xb)
        loss = criterion(out, yb)
        for idx, lam in l2_layers.items():
            loss = loss + lam * model_scaled[idx].weight.pow(2).sum()
        loss.backward()
        optimizer.step()
        running += loss.item() * len(xb)
        running_mae += (out - yb).abs().sum().item()

    model_scaled.eval()
    with torch.no_grad():
        vp = model_scaled(Xva)
        val_loss = criterion(vp, yva).item()
        val_mae = (vp - yva).abs().mean().item()

    history.history["loss"].append(running / len(Xtr))
    history.history["val_loss"].append(val_loss)
    history.history["mean_absolute_error"].append(running_mae / len(Xtr))
    history.history["val_mean_absolute_error"].append(val_mae)
    if epoch % 10 == 0 or epoch == EPOCHS - 1:
        print(f"epoch {epoch+1:3d}/{EPOCHS}  "
              f"train_loss {running/len(Xtr):.4f}  val_loss {val_loss:.4f}")

model_scaled.eval()
with torch.no_grad():
    y_pred_scaled = model_scaled(Xte).cpu().numpy()

print("Validation for testing data")
print(f"R^2 : {r2_score(y_test_scaled, y_pred_scaled)}")
print(f"MSE : {mean_squared_error(y_test_scaled, y_pred_scaled)}")
print(f"MAE : {mean_absolute_error(y_test_scaled, y_pred_scaled)}")
```

### C4 — Imputation and outlier surgery happen before the split (data leakage) 🟠

Cells 20 and 23 compute medians, modes, z-scores and means over the **whole** dataset; the
train/test split only happens in cell 116. Test-set statistics therefore leak into the training
features. `StandardScaler` is fitted correctly on train only — so the notebook already knows the
right pattern, it just isn't applied to the imputation.

Worse, cell 23 also rewrites **the target**: 361 `Loan Sanction Amount` values whose |z| > 3 are
overwritten with the column mean. Those are corrupted labels, and some of them end up in the
test set, which flatters every metric in the notebook.

**Fix.** Never touch the target's outliers. Move feature imputation into a `Pipeline` fitted
inside the split:

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer

pre = ColumnTransformer([
    ("num", SimpleImputer(strategy="median"), numerical_features),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("ohe", OneHotEncoder(handle_unknown="ignore"))]), categorical_features),
])
model = Pipeline([("pre", pre), ("scale", StandardScaler(with_mean=False)), ("gbr", GradientBoostingRegressor())])
model.fit(X_train, y_train)      # every statistic now learned from train only
```

Also note `Dependents` outliers get replaced by the mean **2.25**, i.e. 420 households now have
2.25 dependents. Use the median for count variables, or leave them alone.
